## 2024-05-24 - Vanilla JS Performance: Debouncing Expensive Operations
**Learning:** In a Vanilla JS application without a Virtual DOM, executing full DOM rebuilds (e.g. `renderSidebar`) or performing synchronous I/O operations (e.g. writing large objects to `localStorage` via `JSON.stringify`) on every keystroke are significant main-thread blocking bottlenecks that cause UI thrashing. Specifically for inputs, reading the DOM state should happen immediately to avoid data loss on fast context switches, but the subsequent expensive operations must be debounced.
**Action:** Always wrap high-frequency event listeners (like search inputs or text area edits) with a `debounce` utility to defer computationally expensive DOM updates and synchronous I/O. For operations capturing state, read the value immediately and only debounce the expensive downstream side effect.
