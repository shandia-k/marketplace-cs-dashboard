## 2025-01-20 - Debouncing expensive synchronous I/O on UI events
**Learning:** In a vanilla JS environment without a Virtual DOM, synchronous I/O operations like writing state to `localStorage` via `JSON.stringify` (e.g., `saveScratchpadState`) on every keystroke (e.g., `input` event on a textarea) block the main thread and cause severe UI thrashing. High-frequency event listeners must be debounced.
**Action:** When debouncing event listeners that capture UI state, update the in-memory/DOM state immediately and only debounce the expensive I/O operation. Additionally, always ensure a `beforeunload` event listener is attached to `window` to synchronously flush any pending saves to prevent data loss if the application is closed before the debounce timeout fires. Provide a local fallback for global utilities like `window.debounce` to satisfy automated checks while maintaining runtime robustness, and ensure wrapper functions preserve the `this` context (e.g., `const context = this; func.apply(context, args)`).
