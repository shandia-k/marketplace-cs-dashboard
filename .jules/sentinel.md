## 2025-02-20 - [IDOR in User Profile Operations]
**Vulnerability:** The IPC handlers `get-user-profile` and `update-user-profile` in `src/main/ipc/register-ipc.js` lacked authorization checks, allowing any authenticated user to potentially view or modify the profiles of other users by passing their username.
**Learning:** Operations handling sensitive user data and state over IPC must enforce strict session-based authorization and ownership checks before proceeding to the service layer. Because the frontend and main process communicate over IPC, failure to validate input and enforce authorization boundaries at the IPC entry points leaves the system vulnerable to Insecure Direct Object References (IDOR).
**Prevention:** Always implement 'fail-closed' authorization logic (e.g., explicitly checking `!authService.getActiveSession()`) inside IPC handlers that manipulate user data. Validate that the active session matches the requested target (unless the user is an administrative role like Super Admin) before invoking the underlying service methods.
