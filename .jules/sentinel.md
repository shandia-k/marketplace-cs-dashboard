## 2026-08-05 - Fix Path Traversal in User Configuration Logic
**Vulnerability:** A path traversal vulnerability was found in the `readStores` and `saveStores` functions in `main.js`. The `username` parameter passed to these functions was not validated or sanitized and was being concatenated into a file path (`const fileName = username ? \`stores_${username}.json\` : 'stores.json'; const filePath = path.join(userDataPath, fileName);`). If a malicious user provided a payload like `../../../etc/passwd` via the IPC handler `create-user` or other IPC methods utilizing this logic, it could allow an attacker to read from or write to arbitrary files in the file system.
**Learning:** Path traversal vulnerabilities can occur in desktop applications (like Electron) just as they do in web applications. IPC handlers often receive input from renderer processes which must be treated as untrusted data, even within the same application.
**Prevention:** Always validate and sanitize user input before concatenating it into file paths. Using a regex to strictly allow only expected characters (e.g., `/^[a-zA-Z0-9_-]+$/`) prevents malicious payloads (like `..` and `/`) from traversing directories.
