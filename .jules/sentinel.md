## 2026-08-16 - Path Traversal Vulnerability in Electron IPC Partition Mapping
**Vulnerability:** Electron's `session.fromPartition` was accepting unsanitized user inputs from the renderer via IPC (`clear-store-cache`, `deep-clean-store`, etc.). Attackers could supply partition IDs with path traversal patterns (e.g., `persist:../../tmp`) allowing them to write cache structures or delete arbitrary directories outside the intended cache boundary. In addition, the username used to build the data file path was doing inline replacement instead of a central sanitized method, risking traversal in file loading/saving operations.
**Learning:** Inputs passed from renderer to the main process via IPC handlers directly map to critical Electron native API arguments. Unsanitized strings in filesystem APIs and internal identifiers like partitions introduce critical path traversal risks.
**Prevention:** Always validate strings going into `session.fromPartition` rejecting invalid characters (`/`, `\`, `..`). Extract inline username replacements to dedicated sanitization helpers (`sanitizeUsername`) for consistent application across the filesystem boundary.
