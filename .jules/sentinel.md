## 2025-02-14 - Ensure Fail-Closed Authorization for Sensitive Profile and Store Data
**Vulnerability:** Several sensitive IPC handlers, specifically `get-stores`, `get-user-profile`, and `update-user-profile`, lacked explicit authorization checks. While `save-stores` had a check, it allowed unauthenticated requests to bypass the logic because it only checked `if (currentActiveSession && ...)` which is a fail-open condition.
**Learning:** Checking `if (currentActiveSession && ...)` is inherently fail-open and bypassable. If `currentActiveSession` evaluates to `null` or `undefined` (e.g. unauthenticated request), the condition evaluates to falsy, and execution proceeds, bypassing the authorization check. Authorization logic in Electron IPC bridges should assume the frontend is compromised and validate every state from the backend logic (the main process).
**Prevention:** Always use "fail-closed" logic by checking `if (!currentActiveSession || ...)` to guarantee unauthenticated requests are blocked. Explicitly block requests attempting to fetch or modify data belonging to another user, unless the active session is a Super Admin.
